# Report 003: Go server skeleton and Postgres wiring

## Dev (backend-dev)
Adds a runnable Go service under `server/`. Config comes from env (DATABASE_URL, PORT, PHOTO_DIR), with defaults matching docker-compose, and PORT is validated. The pgx v5 pool connects lazily. GET /healthz returns 200 with db status, or 503 when the DB is down. Logs are slog JSON with method, path, status and duration only: no bodies, queries or IPs. The server shuts down gracefully on SIGINT/SIGTERM. `sqlc.yaml` is prepared with no generated code. The Makefile gets `run` and `test` targets.

Checks: `go vet` and `go test ./...` pass, run in a golang:1.25 container because Go isn't installed locally. The /healthz integration test ran against the compose Postgres. `make test` and `make run` were not run natively, because Go isn't installed.

Open question: go.mod requires Go 1.25 because of pgx v5.13. CI uses `stable`.

## QA
PASS. All acceptance criteria verified in Docker against Postgres. /healthz returned 503 with a bad DSN and 200 against the DB. Graceful shutdown was not confirmed at runtime.

## Reviewer
PASS. 4 minor findings and 3 nits, for follow-up stories: add server Read/Write/Idle timeouts; log the route pattern rather than the raw path (token leak risk); log sanitized Ping errors; require DATABASE_URL in production.
